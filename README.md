# mia-1 backup

Конфигурация сервера ProCloud MIA-1 (84.75.220.37).

## Что здесь

- `config.json` — конфиг Xray (`/usr/local/x-ui/bin/config.json`)
- `x-ui.db` — база панели 3x-ui (`/etc/x-ui/x-ui.db`), содержит инбаунды и клиентов
- `sysctl.conf` — BBR, UDP-буферы
- `sshd_config` — root запрещён, пароли отключены
- `olcrtc-config.yaml` — конфиг olcRTC (эксперимент, отложен)

## Восстановление

1. Поставить 3x-ui
2. `systemctl stop x-ui`
3. Положить `x-ui.db` в `/etc/x-ui/`
4. `systemctl start x-ui` — конфиг Xray сгенерится из базы

## Схема обхода белых списков (Яндекс CDN)

```
Обычные условия:
клиент ──────────────────────────► mia-1 :443 / :8443 / :9443

Белые списки:
клиент ──► Яндекс CDN ──► mia-1 :8043 ──► интернет
        cdn.avqon.com
             :443
```

### Настройки Яндекс CDN

- Ресурс: `cdn.avqon.com`, ID `bc8rtlkbi4k6z3j7xazl`
- Группа источников: `84.75.220.37:8043`, протокол HTTPS
- SNI-хост: `origin.avqon.com`
- Заголовок Host: как у клиента (`cdn.avqon.com`)
- Кэширование: включено, **«Кешировать всё»** для query-параметров, TTL минимальный
- Выгрузка логов и экранирование источников: выключены (платные)
- Цена: 150 ₽/мес, включено 150 ГБ исходящего трафика

### Настройки инбаунда 8043

- `mode: packet-up`
- `uplinkHTTPMethod: GET`
- XMUX: `maxConcurrency = 1`, keepalive period = 60
- `trustedXForwardedFor`: подсети edge-серверов Яндекса
- Сертификат: `/root/cert/origin.avqon.com/`

### Почему именно так

- **Reality через CDN не пройдёт** — своя механика TLS.
- **WebSocket не пройдёт** — Яндекс и CDNvideo не пропускают HTTP Upgrade.
- **Остаётся XHTTP.** Но у Яндекса в разрешённых методах только GET, HEAD, OPTIONS — POST нет и добавить нельзя.
- **Спасает `uplinkHTTPMethod: GET`** — Xray умеет гнать аплинк через GET, но только в режиме `packet-up`.
- Отсюда и задержка: packet-up шлёт россыпь отдельных запросов вместо одного потока.

### Известные ограничения

- Порт в клиентском конфиге приходит 8043, **нужно вручную менять на 443**. Панель не умеет задавать порт для ссылок отдельно от порта инбаунда.
- UDP через CDN не идёт — только TCP. QUIC падает на TCP.
- Около 7% ответов с кодами 5xx в статистике Яндекса.
- Задержка высокая: путь клиент → Россия → Майами → обратно.

### Что пробовали и не помогло

- `stream-up`, `stream-one` — соединение висит, CDN буферизует поток.
- `videochannel` — не применимо.
- `scMinPostsIntervalMs = 10` и `scMaxEachPostBytes = 800000` — стало заметно хуже, откатили. При медленном канале выигрывают крупные и редкие запросы, а не мелкие и частые.

### Идеи на будущее

- Нода в Европе вместо Майами — уберёт трансатлантический участок, плюс 443 там свободен (решит проблему с портом).
- Второй CDN у детей CDNvideo — там есть POST, значит откроется `stream-one`. 0.6 ₽/ГБ.
- VLESS Encryption + XTLS Vision поверх XHTTP — рекомендация автора Xray для связок через CDN.
